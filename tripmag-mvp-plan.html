Step Zero

What Are We Actually Generating?

The prototype's trip.json is 243KB / ~60K tokens. Breaking it down reveals that most data is derivable — the LLM only needs to generate 14% of the content.

SectionSize% TotalMethod
pins (200+ markers)116KB48%Derived
hotels (20+ options)48KB20%LLM + API
days (14 itineraries)21KB9%Core LLM
restaurants (40+ spots)13KB5%LLM + API
everything else44KB18%Computed

48% is Geocoding

Pins are 100% derivable from other sections. No LLM needed — just geocode the place names.

14% is Creative

Days + restaurants are the only sections needing real LLM generation. Everything else is computed or API-sourced.

Schema IS the Contract

types/trip.ts — 389 lines, 30+ interfaces. Every generated trip validates against this.

Generation Pipeline

6 Stages, 2-3 Minutes

243KB of structured JSON can't be generated in one shot. Each stage produces a validated segment.

1
Itinerary Skeleton
Claude Sonnet15-25s$0.14
User preferences → trip metadata + stays + daily activities (names only). 2-shot prompt with examples. Zod validates date continuity and day count.
2
Hotels
Claude + Places API20-30s$0.52
Google Places searchText for hotels per city (10 calls). Claude enriches with descriptions and picks. Names always from API, never invented.
3
Restaurants
Claude + Places API15-20s$0.34
Parallelized with Stage 2. Places API seeds real restaurants, Claude adds dietary flags, cuisine type, and neighborhood context.
4
Derived Sections
Pure TypeScript<1s$0.00
Budget calculator, booking extractor, packing list (template + weather), transport, stats. No LLM — pure computation.
5
Map Pins
Geocoding10-30s$0.05-0.15
Vercel KV coordinate cache (top 500 POIs/city) → Nominatim for misses → Google fallback. Auto-assign categories + route proximity status.
6
Assembly & Deploy
Compose + Upload<1s$0.00
Compose all sections → full Zod validation → upload trip.json to Vercel Blob. Served via dynamic Next.js route /trip/[slug].

Build Plan

8 Weeks to MVP

Two engineers working in parallel. Critical path: schemas → pipeline → template → Inngest queue → E2E.

Weeks 1-2 — Foundation
Pipeline Core
  • Vercel project: Postgres, Blob, KV, Inngest setup
  • Port all 30+ TS interfaces to Zod schemas
  • Stage 1: itinerary prompt engineering + validation
  • Google Places API integration + KV caching
  • Stages 2-3: hotels + restaurants generation
  • Stage 4: derived sections (pure TS computation)
Weeks 3-4 — Integration
Pins + Template + Queue
  • Geocoding pipeline: Nominatim + cache + Google fallback
  • Pin generator: categories, status, day assignment
  • Fork prototype → parameterize (remove Japan-specific UI)
  • Runtime trip.json loading (Blob fetch vs import)
  • Inngest queue orchestration: stage chaining + retries
  • SSE progress endpoint via Vercel KV polling
Weeks 5-6 — Frontend
User App + Payments
  • Trip creation wizard (destination, dates, dietary, budget)
  • Real-time generation progress page (SSE)
  • "My Trips" dashboard with Postgres queries
  • Auth: email magic link + JWT + httpOnly cookies
  • Stripe Checkout integration ($9.99/trip)
  • Payment → generation queue wiring
Weeks 7-8 — Polish
QA + Launch
  • Generate 30 test trips, QA each for accuracy
  • Fix prompts: cross-reference names with Places API
  • Parallelize Stages 2+3, pre-warm caches
  • Mobile responsiveness audit (iOS Safari, Android)
  • Monitoring: Sentry + Vercel Analytics + Postgres metrics
  • Soft launch to 20 beta testers

Risk Matrix

Top 5 Technical Risks

AI Hallucinating Fake Hotels & Restaurants
CriticalHigh Probability
Never generate names from LLM alone. Seed with Google Places API results. Post-validate every name against the original API response. Every listing links to Google Maps for user verification.
Pins Landing in Wrong Locations
HighMedium Probability
Pre-cache top 500 POIs per MVP city with verified coordinates. Bounding box sanity check per city. Use Places API lat/lng as primary source for hotels/restaurants.
Generation Takes >5 Minutes
MediumMedium Probability
Parallelize Stages 2+3 (saves 20s). Pre-warm geocoding cache. Pre-build template (no Next.js build per trip). Transparent progress bar with stage descriptions. Email fallback for >3min.
Serverless Function Timeout
MediumMedium Probability
Vercel Pro gives 300s timeout — enough for single stages. Use Inngest to chain stages as separate function invocations with built-in retries. Each stage completes well within limits. Hobby plan's 60s limit means Pro ($20/mo) is required.
Google Places API Cost Spiral
MediumMedium Probability
Aggressive Vercel KV caching (monthly expiry). Pre-fetch top hotels/restaurants for MVP cities during dev. Combine dietary queries. Hard cap at $1/trip — use LLM knowledge to fill gaps beyond cap.
